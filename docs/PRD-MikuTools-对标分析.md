## 1. 概述

### 1.1 背景

MikuTools（okmiku.com）是中文工具类站点的标杆产品，拥有 148+ 工具、4.3k+ GitHub Stars、月活约 1.5 万。用户评价高度一致："界面简洁清爽"、"没有任何花里胡哨的东西"、"使用体验极其清爽"。本次对标分析旨在提取其设计精华，为 toolorbit 的页面优化提供可执行的参考方案。

### 1.2 目标

- 输出 MikuTools 的设计系统全貌（配色、布局、交互）
- 识别 toolorbit 与竞品之间的关键差距
- 提出分优先级的优化方案，对齐竞品体验标准

## 2. MikuTools 设计系统分析

### 2.1 技术栈

| 维度 | MikuTools | toolorbit（当前） |
|------|-----------|-------------------|
| 框架 | Vue.js + Nuxt.js (SSR) | Next.js 16 (App Router) + React 19 |
| CSS | SCSS（自定义设计系统） | Tailwind CSS v4 |
| 语言 | JavaScript 58.8% / Vue 37.4% / SCSS 1.2% | TypeScript |
| 渲染 | SSR/SSG 混合 | SSR/SSG 混合 |
| 开源 | MIT License（早期版本） | - |

**关键结论：** 两者技术栈不同但设计目标一致（SSR + 工具集）。toolorbit 的 Tailwind CSS 在开发效率上有优势，但需要建立一套设计 token 体系来对标 MikuTools 的视觉一致性。

### 2.2 配色方案

#### 基于源码提取的实际色值

MikuTools 使用 SCSS 变量 + CSS 自定义属性双层主题系统：

**亮色模式（Light）：**

| Token | 色值 | 用途 |
|-------|------|------|
| `--theme` / `$theme` | `#249ffd` | 主品牌色（蓝色） |
| `--theme-success` | `#52de97` | 成功状态 |
| `--theme-danger` | `#fa5477` | 错误/危险 |
| `--theme-info` | `#9ed0ff` | 信息提示 |
| `--theme-warning` | `#ffdd98` | 警告状态 |
| `--border-color` | `#DCDEE0` | 全局边框色 |
| Body background | `#f4f8fb` | 页面底色（浅蓝灰） |
| `--c-primary` | `hsl(171, 100%, 41%)` | 强调色（青绿色） |
| `--c-link` | `hsl(217, 71%, 53%)` | 链接色 |
| `$red` | `#f93a6d` | 强调红 |

**暗色模式（Dark）：**

| Token | 色值 | 说明 |
|------|------|------|
| `--theme` | `#4183c4` | 暗色下主色调整（降低饱和度） |
| `--border-color` | `#6a6a6a` | 暗色边框 |
| Background | `var(--t2)` | 暗色背景（`hsl(0, 0%, 21%)` ≈ `#363636`） |
| Container bg | `#282c34` | 卡片/容器深色背景 |

**设计特点：**
- 使用 HSL 格式的颜色定义，便于动态调整亮度和饱和度
- 暗色模式不是简单反转，而是**降低主色饱和度**（`#249ffd` → `#4183c4`），避免暗色背景下荧光感过强
- 页面底色使用 `#f4f8fb`（浅蓝灰）而非纯白，营造柔和的阅读体验
- 语义化 token 命名（success/danger/info/warning），不直接使用色值

#### 对 toolorbit 的建议

toolorbit 当前使用 Tailwind CSS v4 + 暗色模式。建议：
1. 在 `index.css` 中建立与 MikuTools 对齐的 CSS 自定义属性体系
2. 将品牌色注册为 Tailwind 主题扩展
3. 确保暗色模式下色彩饱和度适当降低

### 2.4 工具页交互模式分类

通过分析多个工具页，MikuTools 的交互可归纳为以下模式：

#### 模式 A：双面板实时编辑器

**代表工具：** JSON 转类型定义、Diff Viewer、Base64 编解码

```
┌──────────────────┐  ┌──────────────────┐
│  输入面板         │  │  输出面板         │
│  (textarea/      │  │  (实时生成的      │
│   code editor)   │  │   结果)           │
│                  │  │                  │
│  粘贴即生成       │  │  支持一键复制      │
└──────────────────┘  └──────────────────┘
    [模式选择器]          [下载/导出按钮]
    [高级选项面板]
```

**交互特征：**
- 输入即输出，无"提交"按钮（实时反应）
- 配置项用按钮组/下拉框切换，切换即时生效
- "复制到剪贴板"是主要的结果消费方式

#### 模式 B：配置 → 上传 → 处理 → 下载

**代表工具：** 图片压缩器、二维码生成器、PDF 工具

```
  [格式选择卡片组]
  [质量参数滑块/下拉]
  [高级选项折叠面板]
  ┌──────────────────────┐
  │   拖拽或点击上传区域    │
  └──────────────────────┘
  [  开始处理  CTA 按钮  ]
  ───────────────────────
  [结果列表（逐项展示）]
  [单项下载] [打包下载 ZIP]
```

**交互特征：**
- 步骤感强：格式选择 → 参数调整 → 上传 → 点击执行 → 查看结果
- 批量处理时逐项展示结果（原大小 → 新大小 → 压缩率）
- 成功/失败状态用颜色区分（绿色=缩小，红色=增大）
- 支持单项下载和批量打包下载

#### 模式 C：即时生成 + 可视化预览

**代表工具：** 二维码生成器、代码截图、ASCII 艺术字

```
  [内容输入框]
  [样式/参数配置面板]
  ┌──────────────────────┐
  │                      │
  │   实时预览区          │
  │   (Canvas/SVG/       │
  │    图片渲染)          │
  │                      │
  └──────────────────────┘
  [下载 PNG] [下载 SVG] [复制]
```

**交互特征：**
- 输入变更即时反映到预览区
- 多种导出格式（SVG / PNG / 复制到剪贴板）
- 样式配置影响视觉输出，预览区实时同步

### 2.5 关键交互细节

| 交互细节 | MikuTools 做法 | 体验价值 |
|---------|---------------|---------|
| 收藏系统 | 心形图标 toggle，无需登录，独立收藏页 | 降低使用门槛 |
| 简洁模式 | 首页 toggle 切换卡片密度 | 兼顾新用户和熟练用户 |
| 搜索 | Hero 区主搜索 + Header 辅助搜索 | 双重搜索入口覆盖不同场景 |
| 分类切换 | 点击 pill 即时过滤，无页面刷新 | 流畅的浏览体验 |
| 工具计数 | Header 显示"共 N 个工具"并动态更新 | 给用户规模感 |
| 移动端 | 底部 Tab Bar（工具/探索）+ 横向滚动分类 | 适配移动端导航习惯 |

| 性能警告 | AVIF/JXL 编码旁标注"比 JPEG 慢 3-10 倍" | 管理预期，减少挫败感 |
| 错误处理 | 批量工具逐项报错，失败项单独列出并给建议 | 部分成功优于全有或全无 |

## 4. 优化方案（优先级排序）

### P0 — 必须做（直接影响核心体验）

#### 4.1 工具卡片增加封面预览图

**现状问题：** 工具列表中的卡片依赖纯文字描述，视觉辨识度低，用户扫描效率差。

**MikuTools 做法：** 每个工具配一张 `cover.png`（148px 宽），展示工具的界面截图或代表性视觉，让用户一眼识别。

**方案：**
- 为每个工具生成/截取一张 `cover.png`，放在 `public/t/{tool-slug}/cover.png`
- 卡片组件增加封面图区域（`aspect-ratio: 16/10` 或固定高度）
- 如果暂时没有截图，用品牌色 + 工具图标 + 工具名自动生成占位封面

**预期收益：** 工具列表点击率预期提升 20-40%

#### 4.2 工具页实现输入即输出的实时反馈

**现状问题：** 部分工具（如 JsonFormatter）需要点击按钮触发处理，多一步操作。

**MikuTools 做法：** JSON 转类型工具在用户粘贴 JSON 的同时，右侧即时生成类型定义代码，无需任何点击。

**方案：**
- 对文本类工具（格式化、编码、转换、Diff）：使用 `useDebouncedCallback` 或 `useEffect` 监听输入变化，300ms 防抖后自动触发
- 保留手动按钮作为 fallback（处理超大输入时避免性能问题）
- 在 UI 上显示"自动处理中"状态（小型 spinner 或文字提示）

**预期收益：** 操作步骤减半，用户停留时长提升

#### 4.3 Hero 区搜索框功能强化

**现状问题：** 需确认当前首页搜索框的交互模式。

**MikuTools 做法：**
- Hero 区搜索框居中、大尺寸、placeholder 为"你想要搜索什么？"
- 输入时即时过滤下方工具卡片
- 与分类 pill 联动（选择分类后搜索范围缩小到该分类）

**方案：**
- 搜索框支持拼音首字母搜索、模糊匹配（工具名 + 描述字段）
- 输入时即时过滤，显示匹配数量
- 搜索框获得焦点时展示热门搜索/最近使用
- 无结果时展示建议工具

#### 4.4 分类导航从下拉/侧栏改为横向 Pill

**现状问题：** 需确认当前分类导航的实际交互方式。

**MikuTools 做法：** 横向可滚动的胶囊按钮行，点击即过滤，当前选中高亮。

**方案：**
- 使用横向滚动容器（`overflow-x: auto` + `scrollbar-hide`）
- 每个分类为 pill 形状按钮（`rounded-full`）
- 选中态：品牌色填充 + 白色文字；未选中：浅灰背景/边框
- 支持"全部"选项清除过滤
- 移动端保持横向滑动

### P1 — 应该做（提升竞争力）

#### 4.5 客户端处理标注

**方案：** 在涉及文件处理的工具页（图片压缩、PDF 转换等），明确展示"全程在浏览器本地处理，文件不会上传至服务器"，增强用户信任感。可设计为一个小型 info banner，带 shield 图标。

#### 4.6 批量操作支持（文件类工具）

**方案：** 对图片/PDF/转换类工具，支持：
- 多文件拖拽上传
- 批量处理后逐项展示结果
- 单项下载 + 打包 ZIP 下载
- 失败项单独列出并给出原因

#### 4.7 工具页内嵌使用说明

**MikuTools 做法：** 工具操作区下方直接以 H2 章节展示使用文档（格式说明、参数指南、注意事项）。

**方案：** 将工具的 SEO 内容/使用说明整合到工具页下方，而非独立页面。提升用户理解成本，同时有利于 SEO（页面内容丰富度）。

#### 4.8 下载选项扩展

**现状：** 当前结果复制到剪贴板为主。

**方案：** 对生成型工具（二维码、代码截图、格式化结果等），增加：
- "下载为 .txt" 按钮
- "下载为 .png"（对可视化结果）
- "复制到剪贴板"（已有）

#### 4.9 简洁模式 Toggle

**方案：** 在工具列表页增加"简洁模式"切换：
- 默认模式：大卡片（带封面图 + 标题 + 描述）
- 简洁模式：紧凑列表（仅图标 + 标题，行内排列，信息密度更高）
- 偏好存入 localStorage

#### 4.10 工具收藏功能

**方案：**
- 每个工具卡片增加心形收藏图标
- 收藏列表页展示已收藏工具
- 数据存 localStorage，无需登录
- 可选：登录后同步到云端

#### 4.11 处理进度与性能预期

**方案：**
- 对慢操作（AI 类、视频处理类）展示进度条或预估时间
- 首次加载 WASM/大模型时给出提示
- 借鉴 MikuTools 的"AVIF/JXL 编码比 JPEG 慢 3-10 倍"警告

#### 4.12 暗色模式主色降饱和

**方案：** 在暗色模式下，将品牌主色的饱和度适当降低（MikuTools 的做法：`#249ffd` → `#4183c4`），避免暗色背景上高饱和色彩造成的视觉疲劳。
