## 文本差异对比工具不只用于代码审查

很多开发者只在 Pull Request 里接触 Diff。实际上，文本对比工具也适合排查接口响应、配置文件、日志和文档变更。

它的价值是把“哪里变了”直接暴露出来。

### 探秘：底层算法是什么？

现代的文本比对工具其核心都依赖于解决“最长公共子序列”（Longest Common Subsequence, LCS）问题。其中最著名的实现便是 Myers 差分算法 (Myers Difference Algorithm)，由 Eugene W. Myers 于 1986 年提出。

Myers 算法会计算将序列 A 转换为序列 B 所需的较短编辑路径，也就是插入和删除的组合。好的 Diff 结果应该尽量符合人的阅读直觉。

### Git 之外的应用场景

独立 Diff 工具常用于这些场景：

#### 1. 遗留系统重构的 API 报文审计
迁移接口时，新旧响应要保持兼容。把旧接口 JSON 放左侧，新接口 JSON 放右侧，Diff 可以帮助发现 `isDeleted: false` 变成 `true` 这类隐藏变化。

#### 2. 环境配置项排障
*“怎么在测试环境跑得好好的，一上生产环境就白屏/连不上库？”* 
这种问题常来自配置差异。把预发布和生产的 `docker-compose.yml` 或 `.env` 放进对比工具，可以快速看到缺失变量、错误 URL 或多余空格。

#### 3. 事故日志的法证学分析
生产节点异常时，可以对比“正常启动日志”和“异常启动日志”。相同流程会被折叠或弱化，分歧点更容易出现。

### 为什么你需要“智能感知 (Smart Diff)”

传统 Diff 基于行。当处理结构化数据时，直接逐行对比可能产生误导。

*   **JSON 与前置格式化能力：** 如果文件 A 是排版精美、格式化好的 500 行 JSON，而文件 B 是其完全相同内容的单行压缩版 (Minified)。传统的 Diff 会告诉你“全量变更，100% 不一样”。而**智能 Diff** 则会在内存中先执行格式规范化（Prettier 化），然后再运行 Myers 算法，最终准确告诉你：数据层面没有任何差异。

### 注意数据安全

不要把业务源码、用户 JSON、生产 `.env` 或密钥粘贴到来源不明的在线对比网站。对方可能记录请求体、错误日志或分析数据。

优先选择纯客户端 (Client-Side Only) 工具，让文本分片、Diff 算法和渲染都在浏览器本地完成。处理敏感内容前，可以用开发者工具网络面板确认输入没有上传。
