# 反推支付手续费：想净收固定金额时应该向客户收多少？

自由职业者、代理商、顾问和卖家经常会遇到一个实际问题：如果我想扣除手续费后净收 $500，应该向客户开多少金额的账单？这就是反推手续费计算。它不是简单地把手续费加到目标金额上。

你可以直接使用 [PayPal 手续费计算器](/tools/ecommerce/paypal-fee-calculator) 或 [Stripe 手续费计算器](/tools/ecommerce/stripe-fee-calculator) 计算结果。本文解释背后的公式。

## 为什么直接加手续费不准确

假设支付渠道费率是 2.9% + $0.30，你想净收 $100。

很多人会这样算：

```text
$100 + ($100 × 2.9%) + $0.30 = $103.20
```

问题在于，客户支付 $103.20 时，支付渠道会按 $103.20 计算百分比手续费，而不是按 $100 计算。

实际手续费是：

```text
$103.20 × 2.9% + $0.30 = $3.29
```

所以你净收到的是 $99.91，不是 $100。单笔看差距不大，但大量发票累计后会变成真实损失。

## 正确的反推公式

正确公式是：

```text
开票金额 = (目标净收 + 固定费) / (1 - 百分比费率)
```

以 Stripe 常见美国国内在线卡费率为例：

```text
目标净收: $100.00
百分比费率: 2.9%
固定费: $0.30

开票金额 = ($100.00 + $0.30) / (1 - 0.029)
开票金额 = $103.30
```

客户支付 $103.30 时：

```text
手续费 = $103.30 × 2.9% + $0.30 = $3.30
净到账 = $100.00
```

## PayPal 反推示例

如果使用 PayPal Checkout，并按常见美元商家费率 3.49% + $0.49 估算，想净收 $100：

```text
开票金额 = ($100.00 + $0.49) / (1 - 0.0349)
开票金额 = $104.12
```

因为百分比和固定费更高，PayPal Checkout 的反推金额通常会高于同金额的 Stripe 标准卡付款。你可以用 [Stripe vs PayPal 手续费对比计算器](/tools/ecommerce/stripe-vs-paypal-fee-calculator) 判断应该发哪个 payment link。

## 哪些场景需要反推手续费

反推计算适合：

- 自由职业者报价固定到手金额
- 代理商通过 payment link 或发票收款
- 顾问希望保住项目净收入
- 卖家接受定制订单
- SaaS 创业者测算支付费对套餐价格的影响
- 创作者售卖低价数字产品

需要注意的是，并不是所有地区或平台规则都允许你把手续费单独转嫁给买家。是否可以加收手续费，要看当地法规、平台规则和支付渠道协议。

## 更好的方式：把手续费纳入价格

很多业务不会在发票上单独写「支付手续费」，因为这可能让客户感觉被额外收费。更自然的做法是把支付成本纳入基础价格，就像你会把软件、服务器、客服、退款和税务成本纳入价格一样。

例如：

```text
目标项目收入: $1,000
预计支付手续费: 约 3%
报价: $1,035 或 $1,050
```

这样比每次向客户解释手续费更清晰，也更符合产品化报价思路。

## 反推计算不包含哪些隐藏变量

反推工具主要处理基础付款手续费，通常不包含：

- 国际卡附加费
- 货币转换
- PayPal 国际商业交易附加费
- Etsy 等平台费用
- 退款政策
- 拒付和争议费用
- 订阅计费附加功能
- 税费处理

高金额或长期合同，建议用真实支付后台报表复核几笔后再固化报价规则。

## 实用流程

1. 确定支付渠道和付款类型。
2. 输入目标净收金额。
3. 复制反推开票金额。
4. 根据业务习惯四舍五入成更自然的价格。
5. 在内部报价备注中记录使用的费率假设。
6. 每月用实际到账复核一次。

## 核心要点

1. 反推手续费不是简单把手续费加到目标金额上。
2. 正确公式需要除以 `1 - 百分比费率`。
3. 固定费对低价发票影响更大。
4. PayPal 和 Stripe 对同一目标净收金额可能给出不同开票金额。
5. 反推计算适合报价规划，最终仍要用支付后台核对。
